# Phase 2.5 — System Improvements

Technical improvements deferred from Phase 2. Implement after all business logic is complete.

---

## Soft Delete for ProjectField + UserFieldValue

**Context:** `DeleteProjectField` with `force=true` currently hard-deletes all `UserFieldValue` records. Irreversible.

**Implementation:**
1. Add `deletedAt DateTime?` to `ProjectField` and `UserFieldValue` in Prisma schema
2. All `findBy*` repository queries filter `WHERE deletedAt IS NULL`
3. Force delete sets `deletedAt = now()` instead of hard delete
4. Cron job purges records where `deletedAt < now() - 24h`
5. Optional: `RecoverProjectField` command (unsets `deletedAt`)

---

## ProjectField Schema Cache

**Context:** `SchemaBuilderService.build()` runs on every `RegisterUser` and `LoginUser` — DB query + Zod rebuild every time.

**Implementation:**
- In-memory `Map<projectId, ZodObject>` cache in `SchemaBuilderService`
- Invalidate on `AddProjectField`, `UpdateProjectField`, `DeleteProjectField`
- Phase 3+: Redis cache for multi-instance deployments

---

## `force: true` SDK Flag for Field Deletion

**Context:** Delete constraint (reject if UserFieldValues exist) is hardcoded. Future SDK should expose this.

**Idea:** `strict: true/false` flag on delete endpoint. `strict: false` skips conflict check and force-deletes.
